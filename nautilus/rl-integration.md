## 1. Bring up the RL container

The RL stack adds one Dockerfile layer on top of env-generator's base image, plus a dedicated compose service that mounts `<repo>` and propagates W&B / GPU env vars.

```bash
docker compose -f docker/docker-compose.rl.yaml build
docker compose -f docker/docker-compose.rl.yaml up -d
docker exec -it loco-mujoco-rl bash
```

## 2. Train a policy

The training entry is `nautilus/scripts/rl/custom_jax/train.py` — Hydra-driven, picks up `nautilus/configs/rl/<algo>.parallel.yaml` for defaults and overlays user CLI overrides.

```bash
# Default budget (config), default task (UnitreeH1)
python nautilus/scripts/rl/custom_jax/train.py --config-name=ppo task=UnitreeH1

# Different algorithm, longer training
python nautilus/scripts/rl/custom_jax/train.py --config-name=sac task=<task_id> total_timesteps=5_000_000

# Fast smoke (few seconds, W&B off)
python nautilus/scripts/rl/custom_jax/train.py --config-name=ppo task=UnitreeH1 \
    total_timesteps=5000 wandb=null
```

`gpu_sim=true` for this benchmark, so train.py uses the **GPU-batched** env factory (your benchmark's batched factory in env_wrapper.create_env()) and reads `nautilus/configs/rl/<algo>.parallel.yaml`. To force the other path one-off, override `gpu_sim=true` (or `false`) on the CLI.

Outputs land in `<repo>/nautilus/outputs/<algo>_<task_slug>_<YYYYMMDD-HHMMSS>/`:
- `checkpoint.pkl` — algorithm checkpoint
- `tb/` — TensorBoard event files (`tensorboard --logdir outputs/`)
- `metrics.jsonl` — one JSON record per metric write (step, key, value)
- `curves/*.png` — training curves auto-plotted at end of training (one PNG per metric key)
- `train.log` — stdout mirror
- `resolved_config.yaml` — Hydra config snapshot
- `render.mp4` + `render_contact_sheet.jpg` — written by render.py (after training)

## 3. Evaluate a checkpoint

`nautilus/scripts/rl/custom_jax/eval.py` is **always headless** and uses the **same vec/parallel env** as train.py (so policy obs/action shapes match). Loads the checkpoint, runs `n_episodes` deterministic rollouts, prints aggregate metrics, writes `metrics.json` next to the checkpoint.

```bash
python nautilus/scripts/rl/custom_jax/eval.py \
    --config-name=ppo task=UnitreeH1 \
    checkpoint=outputs/<trial_id>/checkpoint.pkl \
    n_episodes=10
```

## 4. Render a trained policy

`nautilus/scripts/rl/custom_jax/render.py` is **always single env** (n=1) with offscreen rendering enabled. Loads the checkpoint, runs ONE episode, writes:

- `<checkpoint-dir>/render.mp4`
- `<checkpoint-dir>/render_contact_sheet.jpg` (5-frame sample)

Works on headless hosts because it uses `render_mode='rgb_array'`. To open a live window, use the env's native viewer (e.g. `dm_control.viewer.launch`, `IsaacLab` standalone scripts, etc.).

```bash
python nautilus/scripts/rl/custom_jax/render.py \
    --config-name=ppo task=UnitreeH1 \
    checkpoint=outputs/<trial_id>/checkpoint.pkl
```

## 5. Override hyperparameters

All `nautilus/configs/rl/<algo>.parallel.yaml` fields are Hydra-overridable from the CLI. Common patterns:

```bash
# Different learning rate + longer training
python nautilus/scripts/rl/custom_jax/train.py --config-name=ppo task=UnitreeH1 \
    learning_rate=1e-4 total_timesteps=10_000_000

# Wider network
python nautilus/scripts/rl/custom_jax/train.py --config-name=sac task=UnitreeH1 \
    policy_kwargs.net_arch=[512,512,512]

# More parallel envs (CPU vec-env path; raise n_envs cautiously per benchmark)
python nautilus/scripts/rl/custom_jax/train.py --config-name=ppo task=UnitreeH1 n_envs=16

# Disable W&B for one run
python nautilus/scripts/rl/custom_jax/train.py --config-name=ppo task=UnitreeH1 wandb=null
```

For changes you want to keep, edit `nautilus/configs/rl/<algo>.local.yaml` (created on demand; gitignored if you wish) and Hydra will overlay it. **Do not** edit `nautilus/configs/rl/<algo>.yaml` directly — `rl-integration-generator` overwrites it on every re-run.

## Troubleshooting

- `ImportError` from `nautilus/scripts/rl/custom_jax/train.py` → the algorithm package isn't installed. Re-run `/rl-experiment setup`, or check the Dockerfile pip layer added by Phase 2.
- `wandb: ERROR It appears that you do not have permission to access the requested resource.` → run `wandb login` on the host first; the netrc passes through via the bind mount.
- Trained checkpoint won't load with `eval.py` — algorithm mismatch (e.g. SAC checkpoint loaded with `--config-name=ppo`). The `algo=` flag must match the algorithm that produced the checkpoint.
- `gpu_sim=true` but train fails with `NotImplementedError` from `env_wrapper.create_env` → edit `nautilus/scripts/rl/custom_jax/env_wrapper.py` and wire your benchmark's GPU-batched factory (IsaacGym / IsaacLab / ManiSkill 3 example snippets are in the same function).
- Hyperparameter edits don't stick across re-runs of `/rl-experiment setup` → you edited `nautilus/configs/rl/<algo>.yaml` directly. Use `<algo>.local.yaml` instead.
