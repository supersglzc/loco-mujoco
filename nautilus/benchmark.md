# loco-mujoco — Benchmark Guide

Generated by `benchmark-generator` skill. English-only by contract; regenerated on every re-run.

## About

LocoMuJoCo is a whole-body locomotion benchmark featuring 12 humanoid and 4 quadruped robots, plus 4 (musculo-)skeletal human models. It supports both single-env CPU simulation via raw MuJoCo and massively-parallel GPU simulation via JAX/MJX (and the newer MjWarp backend in v1.1+). The benchmark ships motion-capture datasets (AMASS, LAFAN1, native LocoMuJoCo) for imitation learning, but the same environments expose a plain RL surface via `RLFactory` — that surface is what `benchmark-generator` exercises here.

| Field | Value |
|-------|-------|
| Simulator | MuJoCo (CPU) / MJX (GPU, JAX) / MjWarp (GPU, JAX, v1.1+) |

| Upstream paper / project | https://github.com/robfiras/loco-mujoco — Al-Hafez et al., "LocoMuJoCo: A Comprehensive Imitation Learning Benchmark for Locomotion" (NeurIPS 2023 RoboLearn workshop) |
| License | MIT |
| Primary use case | Whole-body locomotion control — both imitation learning (default) and reinforcement learning |

## Action / Observation spaces

| Field | Value |
|-------|-------|
| Action dim | `19` for `UnitreeH1` (varies per morphology) |
| Action semantics | Joint torques (continuous Box; sampled via `np.random.randn(action_dim)` for the random smoke) |
| Observation type | Proprioceptive state vector (`(52,)` for `UnitreeH1`); Box space exposed via `env.info.observation_space` |
| Control frequency | 100 Hz (`env.info.dt = 0.01`) |
| Reward signal | Dense reward from the configured `Reward` class (default targets walking velocity / posture; pluggable via `loco_mujoco/core/reward/`). RL smoke confirmed finite reward on each step. |

## How to use

`benchmark-generator` provides only the env-sanity layer here: a random-action rollout and an offscreen render-to-MP4. **For training, evaluation, and hyperparameter tuning, see `rl-integration.md`** (rendered separately by `rl-integration-generator` after you run `/rl-experiment setup`). `install.md` (env-generator's output) explains how to build the env (`bash nautilus/setup_uv.sh`).

### 1. Enter the env

```bash
# uv mode — activate the host venv (or just call .venv/bin/python directly)
source .venv/bin/activate
```

### 2. Pick a task

```bash
# loco-mujoco doesn't ship a CLI task-list command; the registered envs live in:
ls loco_mujoco/environments/humanoids/  loco_mujoco/environments/quadrupeds/
# or browse the status table in:
cat loco_mujoco/environments/README.md
```

Any identifier from the task table above is a valid value for `--task`. Identifiers are case-sensitive and use PascalCase (e.g. `UnitreeH1`, not `unitree_h1`).

### 3. Sanity-check the env (random rollout)

`scripts/run_random.py` runs N random-action steps and confirms each `env.step(...)` returns a finite numeric reward. No policy, no checkpoint, no rendering — purely an env-wiring check.

```bash
python scripts/run_random.py --task UnitreeH1 --n-steps 10
```

Expected last line:

```text
L1 OK: 10 steps, all rewards finite
```

If reward comes back `None` / `NaN`, the upstream task isn't returning a numeric reward — surface to the maintainer.

### 4. Render a video of a random rollout

`scripts/render_random.py` runs the same random rollout but with offscreen rendering enabled, capturing one RGB frame per step (`env.render()` returns `(720, 1280, 3)` uint8 directly) and muxing them into an MP4. Proves the GL / EGL pipeline is wired without needing a trained policy or X11.

```bash
python scripts/render_random.py --task UnitreeH1 \
    --n-steps 60 --output /tmp/loco-mujoco_random.mp4
```

Open the resulting MP4 (`vlc`, `ffplay`, etc.) — you should see random-action behavior on the simulated robot. If the file is 0 bytes or the script reports `no RGB frames captured`, MuJoCo's offscreen GL context can't initialise; check that `libegl1`/`libgl1` are installed on the host (env-generator's `install.md` lists them).

### 5. Headed visualization

In uv mode you're already running on the host display, so

```bash
python scripts/render_random.py --task UnitreeH1 --n-steps 500 --output /tmp/viz.mp4
```

will open MuJoCo's GLFW viewer window directly while frames are being captured (assuming `$DISPLAY` is set in the shell). Close the window when done; the MP4 is still written.

## Training

Training scaffolding (PPO / SAC / TD3, configs, eval, render-policy, tune) is **not** generated by `benchmark-generator`. Run:

```
/rl-experiment setup
```

That dispatches `rl-integration-generator`, which writes:

- `nautilus/scripts/rl/{train,eval,render_policy,tune}.py`
- `nautilus/configs/rl/{ppo,sac,td3}.yaml` (+ `.parallel` siblings)
- `nautilus/scripts/rl/<impl>/...` (e.g. `stable_baseline3/` or `custom_default/`)
- `<repo>/nautilus/rl-integration.md` — full Train / Evaluate / Override-hyperparameters walk-through

After that step, follow `rl-integration.md`.

> **Note for JAX users**: `benchmark-spec.json:language="jax"` is set, so `/rl-experiment setup` will refuse PyTorch-only algorithm sources (`custom-default` is PyTorch-based). Pick `local-implementation` to use loco-mujoco's in-tree single-file JAX algorithms (PPO / GAIL / AMP / DeepMimic — see `examples/training_examples/jax_*/`), or `stable-baseline3` if you want to run on a CPU-vectorized adapter (slow for whole-body control — prefer `local-implementation`).

## Troubleshooting

- `L1: reward None / NaN` → upstream task isn't returning a numeric reward. The smoke records FAIL but the rest of the pipeline still completes; surface the issue to the upstream maintainer.
- `L2: no RGB frames captured` → MuJoCo's offscreen GL context can't init. Confirm `libegl1`, `libosmesa6`, `libgl1`, `libglib2.0-0` are installed on the host (`sudo apt install -y libegl1 libosmesa6 libgl1 libglib2.0-0`). env-generator's `install.md` lists these as the apt deps it could not auto-install in uv mode.
- `ImportError: imageio` → re-run `benchmark-generator` Step 3 manually: `uv pip install --python .venv/bin/python "imageio[ffmpeg]"`.
- `RuntimeWarning: os.fork() was called. ... JAX is multithreaded` during L2 → cosmetic; the MP4 is still written. Triggered by `imageio_ffmpeg` spawning ffmpeg via `subprocess.Popen`. Not actionable.
- `TypeError: LocoEnv.reset() got an unexpected keyword argument 'seed'` → expected. The smoke scripts already catch this and fall back to `env.reset()` without a seed.
- Task name not recognised → check the task table above; identifiers are case-sensitive PascalCase (`UnitreeH1`, `AnymalC`, `BDSpot`).
- GUI apps fail with `cannot open display` → confirm `$DISPLAY` is set on the host shell that launched the script. If you're SSHing in, use `ssh -X` or run a local terminal.
- `jax.errors.CudaLibraryNotFound` when running an `Mjx*` task → the `jax[cuda12]` wheel needs CUDA 12 runtime. Confirm `nvidia-smi` shows a CUDA 12-compatible driver; reinstall with `uv pip install --python .venv/bin/python --force-reinstall 'jax[cuda12]'` if needed.
